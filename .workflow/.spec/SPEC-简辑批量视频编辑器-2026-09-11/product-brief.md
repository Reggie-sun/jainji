# Product Brief: 简辑

简辑是一款面向 Ubuntu 的本地批量视频编辑工具。用户创建一次由文字、贴纸和滤镜组成的编辑模板，即可把相同视觉处理应用到一批原始视频，并为每条输入可靠地产生一个独立成片。

## Concepts & Terminology

| Term | Definition | Aliases |
|------|------------|---------|
| 原始素材 | 用户导入且永不被简辑修改或覆盖的视频文件 | 原视频、输入视频 |
| 素材批次 | 本次需要套用同一编辑模板的一组原始素材 | 批次 |
| 编辑模板 | 可保存、复用并应用于整个素材批次的图层与滤镜配置 | 模板 |
| 文字图层 | 具有内容、样式、层级和归一化布局的文字元素 | 文字 |
| 贴纸图层 | 引用本地图片并具有层级和归一化布局的视觉元素 | 贴纸 |
| 全局滤镜 | 作用于整条视频完整画面的单个颜色效果及强度参数 | 滤镜 |
| 验证样片 | 使用最终渲染链路对一条素材产生的预检输出 | 样片 |
| 导出任务 | 一条原始素材与一个冻结模板快照组合后的渲染工作单元 | 任务 |
| 导出批次 | 同一次启动并共享模板快照的一组导出任务 | 导出队列 |
| 输出成片 | 成功导出的独立 MP4 文件 | 输出视频、成片 |

后续文档 MUST 使用上述 canonical term。

## Vision

让重复性视频包装变成一次编辑、整批完成的可靠操作：用户不需要掌握专业时间线，也不需要为每条视频重复设置相同效果。

## Problem Statement

### Current Situation

批量短视频制作者常常需要对多条原始素材重复添加相同品牌文字、角标贴纸和基础调色。通用非线性剪辑软件以单条视频时间线为中心，逐条复制、检查和导出仍然产生大量重复操作；命令行脚本虽然能批处理，但不便预览、保存模板和恢复失败任务。

### Impact

在包含 20 条素材的典型批次中，若每条视频仅花 1 分钟重复配置和启动导出，也会产生至少 20 分钟的机械操作，并增加图层位置、文字内容、滤镜参数或输出命名不一致的风险。

## Target Users

### 批量短视频制作者

- **Role**: 在 Ubuntu 上反复处理同类型短视频的个人创作者、内容运营或小团队成员。
- **Needs**: 批量导入、一次编辑、直观预览、统一参数、可靠导出和失败重试。
- **Pain Points**: 通用剪辑工具操作过重；脚本不可视；逐条导出容易遗漏或覆盖文件。
- **Success Criteria**: 不进入逐条时间线即可完成批量包装，并能明确知道每条输出是否成功及其所在位置。

## Goals & Success Metrics

| Goal ID | Goal | Success Metric | Target |
|---------|------|----------------|--------|
| G-001 | 消除逐条重复编辑 | 一次设置后仍需进行的逐视频编辑操作数 | 0 次 |
| G-002 | 提供可靠、可恢复的批量导出 | 有效输入获得成片或明确失败原因的比例 | 100% |
| G-003 | 保护用户原始素材 | 被修改或静默覆盖的原始素材数量 | 0 |
| G-004 | 降低首次使用门槛 | 新用户完成 2 条视频首批导出的时间 | 不超过 5 分钟，不含编码时间 |
| G-005 | 保持模板在异构素材上的可预测性 | 横竖屏样片中图层保持在指定归一化位置的比例 | 100% |

## Scope

### In Scope

- Ubuntu 桌面端的本地、离线媒体处理。
- 批量导入、检查、选择和移除原始素材。
- 创建多文字图层、多贴纸图层及一个全局滤镜。
- 图层排序、显隐、删除、拖动、缩放及基础样式调整。
- 保存、加载和版本化编辑模板。
- 使用代表性素材进行交互预览，并生成一条验证样片。
- 将冻结的编辑模板应用到素材批次并分别导出 MP4。
- 导出队列进度、失败隔离、取消、恢复和重试。
- 播放输出成片并打开其所在目录。

### Out of Scope

- 时间线裁切、拼接、多轨道编辑和把多条素材合为一个视频。
- 转场、关键帧动画、局部时段图层和复杂合成。
- 音频混音、变速、降噪、语音生成和字幕识别。
- 云端上传、远程渲染、账户、付费和多人协作。
- Windows、macOS、移动端或浏览器托管版发行。

### Non-Goals

| Non-Goal | Rationale |
|----------|-----------|
| 替代专业非线性剪辑软件 | 产品价值是重复任务批处理，而不是完整时间线能力 |
| 用预览替代最终渲染验证 | 浏览器或 GPU 预览可能与 FFmpeg 编码存在细微差异，验证样片才是最终依据 |
| 自动理解或改写视频内容 | 首版只执行用户明确配置的确定性模板 |
| 修改原始素材 | 任何原位编辑都会带来不可接受的数据丢失风险 |

### Assumptions

- 所有文字图层、贴纸图层和全局滤镜在 MVP 中覆盖视频完整时长。
- 输出统一为 H.264 视频、AAC 音频的 MP4；无音轨输入允许输出静音视频。
- 用户愿意安装或允许应用检测系统 FFmpeg。
- 图层位置和尺寸按自动旋转后的显示画面使用 0–1 归一化坐标。
- 默认串行导出，以稳定性和机器可用性优先于最大吞吐。

## Competitive Landscape

| Aspect | Current State | Proposed Solution | Advantage |
|--------|---------------|-------------------|-----------|
| 专业剪辑软件 | 单条时间线能力完整，但重复批处理步骤多 | 以素材批次和编辑模板为中心 | 学习成本和机械操作更少 |
| 命令行脚本 | 可自动化，但预览、错误恢复和模板管理弱 | 可视化模板 + 持久化导出队列 | 非程序用户也能安全复用 |
| 在线批处理工具 | 使用方便，但上传耗时且存在隐私顾虑 | 媒体始终留在本机 | 离线可用且无上传等待 |

## Constraints & Dependencies

### Technical Constraints

- MUST 在 Ubuntu 上运行，并处理来自本地文件系统的大体积视频。
- MUST 保证 UI 与长时编码进程隔离，渲染不得阻塞交互线程。
- MUST 使用同一个 canonical 编辑模板同时驱动预览和最终命令编译。
- MUST 在写入前检测输出路径，不得静默覆盖原始素材或既有输出。

### Business Constraints

- MVP 优先验证重复批处理效率，不扩展为通用剪辑器。
- 首版不依赖付费云服务或媒体上传。

### Dependencies

- Ubuntu 文件系统、文件选择器和文件管理器。
- FFmpeg/ffprobe 兼容版本及对应编解码能力。
- 用户选择的本地字体和贴纸图片文件。

## Multi-Perspective Synthesis

### Product Perspective

差异化不在于效果数量，而在于“模板只设一次、结果逐条可追踪”。MVP 应围绕批量闭环衡量，而不是用专业编辑器的功能列表衡量。

### Technical Perspective

难点集中在预览/导出一致性、不同宽高比的归一化布局、媒体兼容性、长时任务恢复和安全文件写入。FFmpeg 适合作为唯一最终渲染引擎，UI 不应成为第二套输出逻辑。

### User Perspective

主流程应固定为“导入 → 编辑模板 → 导出”，高级参数渐进展开。每条任务必须显示成功、失败、取消或中断状态，错误信息应包含下一步恢复操作。

### Convergent Themes

- 素材批次和编辑模板是产品的两个核心对象。
- 原始素材只读、输出不覆盖和失败隔离是硬性安全边界。
- 交互预览用于快速调整，验证样片用于最终信心。
- 队列持久化和按失败项重试属于 MVP，而不是后续增强。

### Conflicting Views

- 多图层能力会增加 UI 与编译复杂度，但只支持单个文字和贴纸会显著限制模板复用价值；本规格选择“多图层、无时间线”作为边界。
- 内置 FFmpeg 便于安装，系统 FFmpeg 更轻且许可边界更清晰；MVP 先采用启动时能力检测，发行方案保留为 ADR 决策。
