# Summary

提出一个显式选择的“半自动覆盖”模式：自动生成可编辑候选，可选独立视觉复核和一次修正，最后由用户确认实际合成预览，再进入现有导出队列。

本文件是待实施规格，不代表功能已实现、模型已通过验收或用户已批准生产接入。本次仅新增规格；不修改生产代码、调用模型、安装依赖或启动桌面应用。下文 MUST 表示拟实施合同。

核心决定：**降低自动化要求，不把不确定识别改称成功。** 半自动的人工作业结果与严格自动算法的通过率分别统计。独立复核用于发现问题，不能替代最终用户确认，也不能保证两个模型不会一起判断错误。

# Evidence And Baseline

- [多帧定位与真实复测](temporal-cover-localization-2026-09-16.md)记录候选漏检、边界不足及语义误判；其中 Qwen 与 MiniMax 对同一小目标均作出错误的非贴纸判断。API 接通不等于视觉识别通过。
- [成熟方案调研](sticker-cover-prior-art-2026-09-16.md)支持拆分发现、完整边界、语义身份、跨帧关联与重发现；不支持靠反复询问同一坐标保证正确。
- [运行验证](runtime-cover-validation-2026-09-16.md)与[真实覆盖复测](live-cover-retest-2026-09-16.md)仍是失败证据，不能由本规格覆盖为 PASS。
- 当前 [CoverStickerSchema](../src/shared/cover-sticker.ts)仅支持 `manual` / `agent`；手动设置已有逐素材、多框及关键帧能力。单个 `CoverTrack` 只有一个有效区间，关键帧有数量和比例约束。
- 当前 [AgentRunner](../src/main/agent-runner.ts)识别后继续生成方案并入队，没有人工审阅暂停点。[automatic-cover.ts](../src/main/automatic-cover.ts)的临时抽帧会清理，不能直接作为持久审阅证据路径。

# Goals And Non-Goals

| ID | Goal | Success definition |
| --- | --- | --- |
| G1 | 用户能完成本批电商素材的贴纸覆盖 | 可以补漏、改完整边界和出现/消失时段，确认后得到对应成片 |
| G2 | 减少人工逐项核对负担 | 一个问题列表、一处时间线、一次批次最终确认；不为每条模型消息弹窗 |
| G3 | 验证独立复核是否有价值 | 与不使用复核的半自动基线比较漏报、误报、人工修改量、耗时及调用成本 |
| G4 | 保留安全与兼容性 | 旧模式不变；无隐式回退；未确认不入导出队列；冻结重试不再调用模型 |

目标域为本批电商视频中的屏幕贴纸，包括小动画、切镜和出现/消失。困难目标可以转为人工编辑，不能因此宣称算法具备泛化能力。

不包含：擦除/修复原画面、训练模型、保证任意视频零漏检、重写导出队列、自动添加展示文字、固定四角定位、默认启用付费服务、无限重试或本次直接接入生产。复用成熟模块须另行核验许可证、平台、现有环境与真实效果；不在本规格硬指定 SAM 或某一家模型。

# Terminology

- **Candidate**：算法提出的候选，不是已验收贴纸；包括身份、边界与时间证据。
- **Identity**：同一个原贴纸的标识；可以对应多个不连续可见区间。
- **Presence**：`PRESENT`、`ABSENT`、`UNKNOWN`；未检测到不能直接等同消失。
- **Review finding**：复核提出的问题或不确定性，不是可直接执行的模板指令。
- **Human decision**：用户对一个对象或问题的明确处置，可接受、修正、删除误识别或明确不覆盖。
- **Approval**：绑定源素材、当前修订和所有待导出冻结模板的最终确认记录，不是布尔型通行开关。

# Mode Contract

| Mode | Proposed behavior | Export gate |
| --- | --- | --- |
| 覆盖关闭 | 保持现状，不识别、不复核、不生成覆盖层 | 原有制作和导出校验 |
| `manual` | 保持现有逐素材手动框语义 | 原有手动模式校验 |
| `agent` | 保持严格自动模式；不确定或非法结果失败 | 原有严格校验，不切到半自动 |
| `assisted`（新增） | 自动候选或显式人工建稿，可选独立复核，可编辑 | 本规格的人工确认及所有本地硬校验 |

**REQ-01 — Explicit mode.** MUST 由用户明确选择 `assisted`。`agent` 失败只能提示可另行选择半自动，不得自动切换、复用非法结果为有效轨迹或自动导出。模式分派必须显式穷举，不能让新增模式落入现有手动 `else` 分支。

**REQ-02 — Honest status.** 半自动分析失败时保留失败原因和已取得的候选证据；可以进入人工建稿，但 MUST 标记“自动分析未完成”。零候选不能自动变成“无贴纸”。用户可按素材明确选择“不覆盖”，该决定不证明算法无漏检。

**REQ-03 — Unchanged invariants.** 覆盖开关、展示文字、原素材音频与时长、白色不透明覆盖底板、选材与逐轮轮换、角落时段补齐均沿用现有产品合同；半自动不能绕过上传素材、几何、时间、模板或输出文件校验。

# User Workflow

建议流程：

`选择半自动 → 建立候选 → 可选独立复核/一次修正 → 集中人工编辑 → 准备冻结方案和预览 → 最终确认 → 现有导出队列`

**REQ-04 — Editable draft.** 按素材展示全画面、候选列表和时间线。用户 MUST 能在任意位置新增漏掉的贴纸、调整完整覆盖边界、删除误识别、修正出现/消失时间，以及拆分不连续可见区间。身份合并/拆分必须保留明确映射；同一目标的重复候选需要处置，不能重复覆盖。

**REQ-05 — Review surface.** 提供原片与合成预览切换、播放、暂停、逐帧查看、问题定位和区间编辑。关键帧拼图仅用于导航，不能充当完整动态预览。画面应明确区分算法框、模型建议与人工修改；字幕、商品、贴纸是独立可核对的语义标签。

**REQ-06 — Human resolution.** 问题集中列出，并允许连续编辑后统一确认。未解决的问题阻止最终确认；用户可以修正、接受当前方案并明确承担该项不确定性，或明确保留该对象不覆盖。此类处置记为人工决定，不把 `UNKNOWN` 改写成模型证实的 `ABSENT`。不提供默认勾选的“忽略全部问题”。

**REQ-07 — Final preview.** 人工编辑结束后，才准备本轮选材、创作方案、覆盖和角落补齐，并冻结每个待导出版本的实际模板。预览 MUST 使用与导出一致的模板、坐标变换、时间区间和渲染语义。用户可查看所有版本后，一次确认本批次。仅看空框草稿、单个代表版本或静态海报，不得标为最终合成预览已确认。

**REQ-08 — Approval gate.** 最终确认前不得向现有 FFmpeg 导出队列入队。允许明确标识、受控的临时预览媒体，但不得作为正式产物发布。主进程验证确认记录，不能只依赖前端按钮禁用。确认表示用户接受当前结果，不表示已经保证视频每一帧客观正确。

# Independent Review Contract

**REQ-09 — Optional role.** 第一阶段不要求复核 Agent。后续提供独立开关，默认关闭；开启时显式选择可用视觉连接/模型，并显示预计调用数及预算上限。复用现有连接库和凭据 owner，不新增凭据存储或连接管理器，不默认选择 MiniMax，不沿用历史一次性 API 测试授权。

独立指任务上下文和判断过程隔离；同模型也可执行，但必须标明同模型复核，不能称为独立模型交叉验证。生产启动动作需覆盖界面显示的模型请求范围；开发测试仍需单独授权真实账号及商业额度。

**REQ-10 — Independent evidence.** 复核包含两个隔离步骤：先在未标注全画面及相邻原帧中自行检查可能遗漏的目标，再对照候选及单目标放大裁剪检查身份、完整边界、重复身份和时间范围。第一步请求不得包含候选、标注或前一 Agent 的结论；先校验并保存其响应，再向第二步提供对照证据，不能在同一请求中要求模型“先假装没看过答案”。两个步骤分别计入预算，证据与结果分开保存。

两步输入均包含素材内部标识、原帧 PTS、尺寸和实际使用的裁剪/缩放变换；候选 ID 及候选标注仅在第二步提供，避免拼图目标指向混淆且保持第一步盲检。只检查已有候选无法发现所有漏检，因此全画面检查不可省略。模型结论必须指向实际提供的证据；不能编造未观察帧的结论。

**REQ-11 — Structured findings.** 复核输出仅包含绑定当前草稿修订的问题：`missing_target`、`incomplete_boundary`、`wrong_semantics`、`duplicate_identity`、`uncertain_presence` 或 `insufficient_evidence`，以及证据帧、对象/区间、理由和建议。允许 `no_issue_observed`，但不等同逐帧证明正确。模型置信度和模型一致投票均不能直接产生导出批准。

模型不能执行工具、改文件、直接写最终模板或批准导出。新发现和建议坐标必须重新进入候选/本地校验流程；异常响应是复核失败，不是空问题列表。

**REQ-12 — Bounded correction.** 默认且首版硬上限为两轮复核、一次自动修正：第一轮复核 → 针对问题修正 → 第二轮复核。没有问题可以提前结束；无新证据、没有改善、反馈冲突或第二轮仍不确定时进入人工处理，不继续循环。人工改稿后不自动重启付费复核；再次运行必须显式发起新的预算受控运行。

**REQ-13 — Request budget.** 每次复核运行先冻结请求计划：首轮两个步骤的批次数、最多一次修正的请求数、第二轮两个步骤的批次数，以及复核总 `maxRequests`；每个 HTTP 模型请求（包括失败请求）均占额度。实际调用不得超过计划，额外抽帧或扩批需要新运行及明确确认。候选分析、选材与创作调用另列阶段预算，在各阶段开始前展示并绑定用户启动动作，不能藏在复核预算之外自动追加。已用请求数/耗时必须可见；无可靠计价时显示“费用未知”，不得虚构金额。

请求开始后连接不可切换；取消停止后续请求并取消可取消的在途请求。超时、额度错误、协议错误或预算用尽不得静默重试、换模型或报复核通过。保留草稿，用户可明确选择人工完成并确认“复核未完成”，或者终止；这是半自动人工处置，不是严格自动回退。

# Geometry And Temporal Contract

**REQ-14 — Full-frame discovery.** 自动候选搜索全画面，不允许四角位置、人工离线真值或已知坏框作为隐藏种子。人工补框仅作为 `assisted` 的显式输入，必须标注来源；不得混入自动定位实验成绩。切镜只触发重新验证，不能自动结束屏幕贴纸区间。

**REQ-15 — Complete boundary.** 边界覆盖完整图案而非最高模板分数对应的局部。保留原分辨率核对证据和坐标变换；渲染继续向外取整到输出像素。小动画、文字部件与装饰射线应纳入核对。框超出画面、数值非法、区间非法或模板不支持时必须拒绝，人工确认也不能绕过。

**REQ-16 — Presence and segments.** 编辑及证据时间以解码帧 PTS 为依据，不假设所有视频为恒定帧率。可见区间约定为 `[startMs, endMs)`，必须有可解释的帧映射；切镜、快速变化与未观察部分可保留 `UNKNOWN`。只抽样观察的结果不得标为逐帧已验证。

同一身份可有多个不相交区间；转换为现有单区间轨迹时逐段生成，不得跨消失间隙插值。沿用现有轨迹的关键帧数量、比例和合法性要求，无法无损表达则提示人工调整或明确失败，不能偷偷截断关键帧、拉大框或延长时间。最终覆盖区间以用户确认的编辑结果为准，算法 presence 证据保持原样。

# State And Persistence Contract

下列状态是现有制作流程内新增的审阅准备子状态，不是第二套导出队列：

| State | Meaning | Allowed next step |
| --- | --- | --- |
| `draft` | 尚未分析或显式人工建稿 | `analyzing` / `needs_human` |
| `analyzing` | 获取候选与证据 | `reviewing` / `needs_human` |
| `reviewing` | 有预算的复核及一次修正 | `needs_human` |
| `needs_human` | 人工编辑、处置问题 | `preparing_preview` |
| `preparing_preview` | 生成并冻结所有版本模板、准备预览 | `awaiting_approval` |
| `awaiting_approval` | 等待最终批次确认 | `approved` / `needs_human` |
| `approved` | 主进程已验证批准与冻结方案一致 | 进入现有队列 |
| `stale` | 源文件、证据或批准绑定已失效 | 明确重建，不自动调用模型 |
| `cancelled` / `failed` | 用户终止 / 不可恢复错误 | 显式重新发起 |

**REQ-17 — Single lifecycle owner.** 等待人工不占用在途模型调用槽。用户编辑前结束或取消在途分析；请求响应绑定 `runId`、`draftRevision`，晚到或旧修订响应不得覆盖新草稿。取消适用于分析、复核、准备预览和导出前等待，不能取消后仍入队。准备预览失败保留草稿但禁止批准；不进行静默模型重试。

**REQ-18 — Approval binding.** 批准绑定项目/素材 ID、源文件指纹、草稿修订、人工决定集合、输出设置、全部版本的不可变模板摘要及依赖贴纸资产指纹。模板摘要包含实际展示文字、图层、轨迹、渲染策略及角落补齐结果。主进程在入队前再次验证绑定和源/依赖资产；客户端传入 `approved: true` 无效。

任何影响输出的编辑、素材替换、选材或版本数量变动使相关预览和批准失效；重新冻结和确认后才能导出。已经入队的任务继续持有原有不可变快照，后续草稿编辑不能反向改写它。跨素材确认不得混用修订。

批准提交与入队须通过现有任务 owner 的持久化幂等交接，以批准 ID 和版本 ID 标识每项任务并保存对应的现有任务 ID。重复提交返回原任务；重复点击、IPC 重放或部分入队后重启不能创建重复导出。恢复时先核对已存在任务，仅显式继续尚未入队的版本，不能重新调用模型补全已冻结方案。

**REQ-19 — Durable draft.** 复用项目 schema/migration 与现有 store 持久化路径，保存可恢复草稿及最小复核/批准记录。证据文件由单一受控本地目录 owner 管理，以引用和摘要关联，不能依赖分析函数已删除的临时文件。文件缺失或摘要不符时明确标为证据缺失并阻止旧批准复用。

重启恢复草稿时不得自动分析、调用模型或开始导出。尚未入队的批准恢复为待用户继续，重新校验后才能显式提交；已入队任务按现有冻结任务恢复规则处理。保存需绑定项目和修订，异步旧保存不能覆盖新编辑。

**REQ-20 — Frozen retry.** 同源素材的识别草稿可供本次多个版本共享，批准覆盖各版本实际模板。正式入队后，重试复用冻结模板、选材和轨迹，不再次识别、复核或换款。源/贴纸资产已变化时沿用现有失效处理，不偷偷更新快照。

最小数据合同如下；字段名供实现对齐，不是当前已存在的接口：

| Record | Required information |
| --- | --- |
| Draft | `draftId`、`runId`、project/media ID、source fingerprint、revision、mode、status、identities、segments |
| Candidate evidence | 原帧 PTS/尺寸/摘要、候选边界、presence、坐标变换、算法来源及版本；人工编辑单独记录 |
| Review attempt | round/batch ID、输入摘要、draft revision、连接/模型非敏感标识、请求状态、耗时、用量、findings |
| Human decision | issue/identity/segment 引用、采取动作、作用修订、时间；未知项的显式接受或不覆盖决定 |
| Approval | 稳定批准/提交 ID、revision、决定摘要、素材及依赖资产指纹、全部冻结模板摘要、批准时间、逐版本待入队/已入队状态及现有任务 ID 映射 |

**REQ-21 — Compatibility and privacy.** 旧项目保持原模式解释和旧单框兼容；新增模式采用显式 schema 迁移，旧版本不得把未知模式静默当成手动。实现必须声明最低可读取版本并在不兼容时清晰拒绝。API Key 不进入草稿、日志、证据或模型消息；使用现有凭据 owner。只发送必要抽帧/裁剪和非敏感上下文，不发送原视频、本地路径或凭据。模型输入均视为数据，不能改变权限边界。

# Evaluation And Release

**Phase 1 — Semi-automatic baseline.** 先交付候选草稿、人工编辑、真实预览、批准绑定和冻结导出；不依赖第二个模型可用。通过对应 AC 后，可称“半自动功能可用”，不能称“自动定位通过”。

**Phase 2 — Independent review pilot.** 复核默认关闭，显式启用后只提出问题，不自动修改；沿用人工最终批准。先证明它能发现已知漏检/误分类，而不是只复述前一模型。

**Phase 3 — Bounded correction.** Phase 2 证据支持后，才开放一次修正及第二轮复核。仍无全自动放行；反馈恶化或预算耗尽直接交人工。

阶段追踪：G1/G2 对应 REQ-04–08、14–16；G3 对应 REQ-09–13、22；G4 对应 REQ-01–03、17–21。Phase 1 验收 AC-01–03、08–15、17；Phase 2 增加 AC-04–07、16，其中 AC-06 此时验证仅一轮、无自动修正；Phase 3 再验证 AC-06 的完整两轮上限。

**REQ-22 — Separate evidence and scores.** 验收数据必须在调参前冻结，划分开发集和未参与调参的留出集，记录原视频来源、片段范围和摘要。同源相邻片段不能冒充独立泛化样本。标注覆盖贴纸/字幕/商品、动画、切镜、出现/消失及无贴纸负样本；人工离线真值不得传给自动候选或复核模型。

分别报告候选召回、完整边界、语义误判、presence/区间误差；复核的真问题发现与误报；人工修改数、明确跳过数、操作耗时；模型请求数、延迟和实际可得费用；最终媒体检查与用户观看结果。人工作业输入与离线评测真值分离，保留“机器建议→人工决定”的变化记录。

Phase 2/3 的启用结论采用同一冻结数据集的配对比较：有复核与无复核均完成相同任务，平衡观看顺序以减少熟悉度影响。报告逐片结果及中位人工操作耗时；只有已知严重问题未被隐藏、最终人工验收质量不降低、人工操作耗时中位数下降且所有运行遵守预算，才建议继续推广复核。实际样本数、覆盖范围和总等待耗时必须披露；小样本只能叫试点结果。

这不是自动化算法零错误 gate 的放宽证明。若要重新宣称严格自动通过，仍需独立执行原有完整边界、无漏检/误识别、唯一身份和确定时段 gate；任何已知失败不能被“用户最终接受”从自动失败统计中删除。

# Risks And Open Decisions

- 相关性错误：不同模型可能都看错小目标；完整画面、单目标裁剪和人工确认只能降低风险，不能证明零漏检。
- 审阅成本：额外 Agent 可能增加等待且不减少操作，因此先建立半自动基线，不默认启用复核。
- 表达能力：现有轨迹对比例和关键帧数的限制可能使复杂动画只能人工选择保守覆盖；无法合法表达时停止，不改小 gate。
- 证据存储：实现前确定受控目录、引用回收和容量策略；草稿/批准仍引用的证据不得被自动清理，清理不涉及源视频。
- 推广决定：复核服务选择、冻结评测清单和每次请求预算必须在对应真实试点开始前明确；本文件不授权额外商业调用。
