# Summary

为原视频建立可持久保存、按素材内容匹配、经过主管看图核查的贴纸知识。首次制作通过执行 Agent、主管 Agent 与实际样片得到可复用的原贴纸位置和出现时段；后续批次复用这些事实，继续独立创作包装并检查新样片。新证据发现错误时修订知识，避免不同版本反复犯同一个定位错误。

本文件是待实施规格，**不代表功能已实现或验收通过**。本次只编写规格与实施计划；下文 MUST / SHOULD 表示未来实现合同。实现不要求增加 Agent 数量，也不绑定某一家模型。自动模式继续由 Agent 完成检查，不新增逐条人工确认步骤。

对应实施顺序、代码归属与验证入口见 [Implementation Plan](source-sticker-knowledge-plan.md)。

# Evidence And Current Behavior

参考 session `01a0aae9-7228-76d2-801a-b2c5dc631b28` 的实际操作：自动识别失败后，在用户授权代看并接受误差的前提下，Codex 查看多帧联系表，按素材设置覆盖范围、排除商品与普通字幕，再交给创作模型设计并抽查成片。氨糖膏的 16 条素材保存了 39 个覆盖区域；后续批次复用这些区域。马油使用看图后的四角覆盖，蝴蝶贴复用用户原先确认的范围。该过程证明了“看图决定、保存、复用”的价值，不能作为无人干预自动识别通过率。

当前代码已实现执行 Agent 提议、主管修正、真实样片复核，见 [验证记录](agent-supervisor-validation.md)。已有事实：

- [AgentRunner](../src/main/agent-runner.ts) 使用 `pendingCoverTracks` 在单次运行中共享识别结果，运行结束后清理；没有跨批次的原贴纸知识。
- [supervised-preview.ts](../src/main/supervised-preview.ts) 返回通过检查的模板；样片修正后的原贴纸事实没有作为独立修订传播给同素材其他版本或后续批次。
- [supervisor-protocol.ts](../src/main/supervisor-protocol.ts) 已有受限的补帧、修正及通过协议；识别窗口最多 3 轮主管调用，样片最多 5 轮检查、2 次有效修订。
- 基线的 [automatic-cover.ts（现存历史测试 fixture）](../tests/helpers/legacy-automatic-cover.ts) 在前 3 秒模式下只分析所需时段；模板中冻结的轨迹用于本次渲染，不代表已观察完整视频。
- 当前 [半自动规格](semi-automatic-cover-review-spec.md) 的人工批准属于 `assisted`。其历史基线描述不能覆盖当前代码，也不能作为本功能取消自动模式或导入人工批准的依据。

现有真实验证曾出现误识别原贴纸导致缺角，以及主管误解 3 秒边界；因此不能仅缓存模型说过的 `pass`。知识身份、证据、适用时段和修订一致性必须一起约束。

# Goals And Scope

| ID | Goal | Observable outcome |
| --- | --- | --- |
| G1 | 复用已核查的原贴纸事实 | 同一素材再次制作时，命中有效知识的时段不重新调用原贴纸识别及其主管识别阶段 |
| G2 | 传播正确修订 | 一个版本修正原贴纸后，同素材尚未入队的受影响版本使用新修订重新检查 |
| G3 | 保留包装多样性 | 选款、价格外观、支持的滤镜仍按原规则逐版本生成；知识不携带固定包装方案 |
| G4 | 兼容三种使用意图 | 关闭覆盖只补角，自动覆盖使用已有事实生成覆盖层，手动与半自动操作保持原语义 |
| G5 | 能解释效果和节省 | 可追溯命中、失效、修订原因，分别统计识别调用、样片调用、耗时和实际画面问题 |

首版范围为当前应用本地用户目录内的跨运行、跨项目复用，以及同源多版本修订一致性。完全相同的文件副本可以共享；仅画面相似、同一商品、文件名相同或重新编码的视频不可共享。

不包含：训练或微调模型、语义视频去重、云端同步、共享其他用户知识、自动导入历史人工框、修改原视频、抹除图像、生成新素材、重新设计模型连接或导出队列。独立包装版本仍须检查实际样片；本规格不承诺任意素材零漏检。

# Core Distinctions

| Concept | Meaning | Reuse boundary |
| --- | --- | --- |
| Source knowledge | 原画面中哪些对象属于后期贴纸、其边界与出现时段，以及已核查范围 | 匹配源文件、时域与解释合同后可跨批复用 |
| Source evidence | 原帧、实际解码时间、局部放大映射、主管结论及修订理由 | 证明实际查看过什么，不能扩大为逐帧正确保证 |
| Render decision | 本版本覆盖层、补角时段、款式、大小和文字外观 | 由源知识及本轮输入重新生成 |
| Preview verdict | 某个冻结模板及实际样片的检查结果 | 仅绑定该模板、素材、依赖及输出设置，不能跨版本通用 |
| Manual instruction | 用户希望覆盖或保留什么的明确决定 | 是编辑意图，不能自动提升为客观原贴纸事实 |

**REQ-01 — Separate facts from styling.** MUST 只持久复用原贴纸事实。新增贴纸的位置、为遮住原贴纸而放大的覆盖框、款式、上传贴纸 ID、价格、滤镜、导出分辨率及用户“不覆盖”决定不得成为源知识字段。保留必要的语义分类和排除理由即可，不持久提取或生成价格、广告文案。

**REQ-02 — Qualified verification.** 知识中的“已核查”表示主管基于记录的原帧及配对样片作出判断并通过本地校验，必须标注 `sampled`，不能称为逐帧证明或人工验收。两个角色使用相同模型时记录这一事实，不称为跨模型交叉验证。

# Source Identity And Temporal Coverage

**REQ-03 — Exact source identity.** 复用键 MUST 包含源文件 SHA-256、字节数、解码后方向/尺寸与时间基准解释版本。读取候选后、送入制作前使用现有素材指纹机制校验实际文件；路径、文件名、project/media ID、时长相同均不足以命中。路径只由本地素材 owner 管理，不发送给模型。

文件改名或复制且内容与解释合同完全相同，可以复用；同路径内容变化必须走新源身份。源文件在运行中变化时停止该素材，不能静默重新识别后继续。解码解释版本变更只有在实现明确声明兼容时可复用。

**REQ-04 — Explicit coverage.** 知识 MUST 记录 `reviewedRanges`，区间为源时间轴上的 `[startMs, endMs)`，并分别保留抽样帧 PTS、presence 判断和插值来源。已核查某区间表示该区间按记录的采样策略处理过，不代表每个时刻都有证据。没有观察到目标、请求失败和未分析区间不得自动变成 `ABSENT`。

- 新制作中，前 5 秒模式仅影响手动展示文字 / 价格，贴纸全程显示，因此仍要求 `[0, durationMs)` 的可用事实。历史冻结模板没有 `stickerDisplayMode: full` 标记时保留旧的前 3 秒联合时序；3 秒后的原贴纸保留不构成错误。
- 全程知识可以按所需时段取子集；仅前 3 秒知识不能满足全程模式。
- 首版若有效知识不能完整覆盖所需时段，整段所需时域重新识别，并与重叠旧证据核对；不拼接可能身份冲突的局部轨迹，不自动扩展请求预算。
- 无贴纸结果也必须绑定已核查区间和原图证据。空数组不能代表整段视频无贴纸。

**REQ-05 — Source geometry.** 边界 MUST 相对正向解码后的完整源画面归一化，包含图案的可见边界及描边；输出补边、缩放、覆盖白底和安全扩边在现有布局/编译 owner 中计算。知识不得存成输出画面坐标。同目标不连续出现必须分段，不跨消失区间插值；沿用现有轨迹数量、关键帧、比例与时间校验。

# Analysis And Reuse Workflow

主流程：

`用户开始制作 → 校验原有准入 → 校验素材并查知识 → 复用或执行识别/主管核查 → 逐版本创作 → 本地生成图层 → 渲染并检查样片 → 修订一致性检查 → 冻结并进入原导出队列`

**REQ-06 — First analysis.** 未命中时复用当前执行/主管流程。提供带时间的全画面证据，按需要补帧与局部放大，区分贴纸、普通字幕、人物与商品实物。主管可以修正执行结果，但不能把“某类电商素材通常四角有图标”当成实际观察；不得通过固定四角框完成首次定位。

在现有窗口识别后，必须将整个所需时域的候选身份、关键证据及未解决问题交给首轮样片主管，形成素材级检查上下文。证据过多时使用有界摘要和按需取帧，摘要保留实际时间引用，不伪造看过的帧，也不无限增加单次请求。

**REQ-07 — Warm reuse.** 有完整可用知识时，跳过该素材的执行识别和主管识别调用。原有创作、选材、本地几何校验和每个新版本的样片复核继续运行；样片主管取得原图、当前知识修订及新成片，而非只看到历史“通过”。更换模型连接本身不修改既有事实，模型来源作为审计信息保留；明确重新检查时使用当前冻结的连接。

首版保持已有连接准入：自动路径仍要求识别、主管及创作所需连接就绪，不能靠缓存绕过连接配置检查。不同角色可共用同一 API/模型，运行期间不切换连接。

**REQ-08 — Publication gate.** 候选知识只有在以下条件同时成立时才可成为可复用修订：源身份校验通过；全部所需区间的结构、时序和边界合法；主管实际核查原图且没有未解决的事实问题；至少一个精确绑定该候选修订的真实样片通过；证据已持久化并校验摘要。

仅有模型 `pass`、模板合法、FFmpeg 成功或用户接受较大覆盖误差均不足以发布源知识。布局修订不得伪装源事实修订；只改变尺寸/旋转时不新增源知识版本。

**REQ-09 — Limited corrections.** 保持现有每个识别窗口最多 3 次主管调用、每个版本最多 5 次样片检查和 2 次有效修订。非法或无效修订消耗检查轮次；存在未解决问题时不能直接改报通过。为旧版本应用新知识并重新检查也计入该版本原预算，不重置预算或另开隐藏循环。达到上限则该版本失败，已通过且未受事实争议影响的版本按原规则继续。

必须区分源事实无变化与渲染无变化。关闭覆盖时，同一角内原贴纸边界纠正可能不改变补角画面，但仍是有价值的事实修正。此类修改只有绑定具体源事实问题、原图证据和实际字段差异并通过本地校验，才计为一次有效修订；仍须重新渲染、检查并将新结论绑定新事实摘要，即使像素一致也不能继承旧批准。源事实与有效图层均无变化才属于完全 no-op。仅事实变化不能自动解除缺角、重复角标或误盖等尚未实际解决的成片问题；不能通过无关的坐标微调清除未解决问题锁定。

知识命中只减少识别工作，不承诺总调用或耗时一定减少。API 错误、超时、额度不足不触发自动换模型、降级手动或无限重试。

# Revisions And Consistency

**REQ-10 — Immutable revisions.** 每个候选绑定 `sourceKey`、基础知识修订、当前运行、证据集合及所需时域。发布生成不可变新修订；旧修订保留用于审计和历史冻结任务。记录何处由旧事实改为新事实、对应原图证据及改动理由，禁止只存“最新框”覆盖历史。

| State | Meaning | Reuse |
| --- | --- | --- |
| `candidate` | 本轮尚未通过发布门槛的观察/修正 | 仅本轮内部使用，不能跨运行命中 |
| `reviewed` | 已满足发布门槛的不可变事实修订 | 身份、时域及合同匹配后可复用 |
| `disputed` | 有绑定原图的具体反证，尚未解决 | 暂停作为新制作的知识来源 |
| `superseded` | 已由新的核查修订替代 | 仅供审计、已冻结任务引用 |
| `unusable` | 证据损坏/缺失、源解释不兼容或 schema 不可读 | 不能命中，显示明确原因 |

`disputed` 不是模型一句“可能有问题”就能写入：必须有合法的问题类型、作用目标/区间及实际原图证据引用。格式错误、网络失败、外观不满意或旧轨迹在 3 秒结束，均不得撤销已核查源事实。若具体矛盾成立但预算不足，保留问题并阻止后续静默复用旧修订。

反证保存独立于成功知识发布。对已有可复用修订，一旦原图绑定和结构校验通过的具体反证成立，必须先持久记录争议、受影响修订/时域与必要证据，再进行修正；不能等到新样片通过才保存。预算耗尽、后续失败或用户取消都不能清除已成立的争议；这只撤回旧事实的复用资格，不是发布新事实，也不授权额外模型调用。取消前已确认的本地反证交接应安全完成，取消后的迟到模型响应不得新增决定。

**REQ-11 — Same-source propagation.** 样片阶段纠正原贴纸后，必须返回独立的知识修订结果，不能只返回渲染模板。运行内按 `sourceKey` 共享当前事实修订，不依赖临时 media ID。其他待生成版本使用新事实；已经生成但未入队的受影响版本，其旧样片结论失效，必须重新构建相关图层、渲染并检查。

主管修改不同时间段时，只影响与该修订相交的版本适用范围；实现无法可靠判断影响范围时，以该素材全部未入队版本为受影响。正式提交前再次核对版本绑定与知识修订。出现新反证不能仅修复最后一条、把此前已知错误的版本一起导出。

**REQ-12 — Concurrency and cancellation.** 同一源的发布使用基础修订比较及原子提交。完全相同的事实/证据提交幂等；并发冲突不得按最后写入覆盖，也不能混合两套身份。冲突方停止当前发布并报告，后续显式运行再处理，不自动追加模型调用。知识重新检查、作废与最终队列交接由主进程串行协调，不能出现入队前校验和实际提交之间的旧修订放行。

取消、超时、崩溃和旧响应不得发布未完成候选、覆盖新修订或继续入队。已原子发布的知识在取消后可以保留，其发布门槛不得减弱；尚未发布候选仅作诊断，恢复应用不自动继续付费请求。若知识写入失败，只有不存在修订冲突或未解决反证、且仍能核对当前有效修订时，才允许本轮已通过的冻结模板按原导出流程继续，并标明“本次结果未保存供复用”；否则停止，不能把冲突当普通缓存写失败绕过。下一批不可假装命中未保存结果。

**REQ-13 — Frozen jobs.** 已入队的模板、素材快照与依赖按原队列合同冻结。后续知识修正不反向改写历史任务；导出重试不读取当前知识、不重新识别或换款。旧修订被质疑时应提示历史结果可能受影响，但不得自动重做、删除、撤销或改变重试方案。用户重新生成包装才使用当前可用知识。

# Modes And Invalidation

| Change or mode | Source knowledge behavior | Required render behavior |
| --- | --- | --- |
| 关闭覆盖、自动装饰 | 读取匹配的原贴纸占位 | 只补空缺角落/时段，不生成覆盖层 |
| 开启自动覆盖 | 可以读取同一份原贴纸事实 | 按本轮选款生成覆盖及补角，重新检查实际样片 |
| 手动覆盖 / `assisted` | 不自动改写手动框、人工决定或批准 | 维持现有模式与批准门槛 |
| 展示文字、款式、滤镜、分辨率改变 | 不使源事实失效 | 旧样片批准不能复用，新模板重新检查 |
| 价格前 5 秒改全程 | 新制作的贴纸均需全程知识；旧 3 秒知识不足则未命中 | 识别完整所需时域后再制作 |
| 文件移动 / 相同字节副本 | 重新校验身份后可命中 | 冻结当前有效源路径，路径不进入知识键 |
| 同路径换文件 / 重编码 / 源解释不兼容 | 未命中或不可用 | 不自动套用旧位置 |
| 模型更换 | 已核查事实不因模型名称改变而作废 | 记录本轮模型，支持显式重新检查 |
| 有证据的新反证 | 相关修订进入争议，禁止新命中 | 本轮有界纠正或失败，不能忽略问题 |

**REQ-14 — Manual provenance.** 旧人工框可能为遮挡而扩大，也可能遗漏未打算覆盖的贴纸。首版不自动把 `manual`、历史 `reviewDrafts` 或已导出模板转成源知识。尤其“不覆盖”不代表“无原贴纸”。后续若支持用户主动导入，必须作为有来源的候选重新核查，不继承半自动批准，不计为纯自动首次识别成绩。

**REQ-15 — Explicit refresh.** 提供“重新检查原贴纸”操作，作用于选定素材的下一次明确制作运行；一次性跳过知识命中，沿用同一预算及模型连接规则。点击仅设置制作意图，不自行发起付费调用。刷新失败不把失败候选写成成功，不隐式回退旧知识完成本轮；没有可信反证时，旧核查记录仍保留供之后明确发起的普通制作使用。

# Persistence And Ownership

最小领域合同如下。字段名用于实现对齐，不表示当前 API 已存在：

| Record | Required fields |
| --- | --- |
| Source identity | 内容指纹、字节数、正向尺寸/旋转解释、源时间基准、解释合同版本 |
| Knowledge revision | ID、父修订、事实摘要、适用时域、目标身份与分段轨迹、语义排除、核查状态及 `sampled` 标记 |
| Evidence | 实际帧 PTS、原图/裁剪摘要与坐标映射、候选和问题引用、配对样片帧、对应模板及输出设置摘要 |
| Dispute | 受影响旧修订及区间、问题类别、实际原图反证、阻断状态；不依赖新知识发布成功 |
| Review provenance | 执行/主管模型非敏感标识、合同版本、请求结果及次数、修订理由、时间；不得包含密钥或登录 token |
| Frozen reference | 制作实际采用的知识 ID/修订/摘要；模板仍冻结完整渲染数据，引用不是重试的运行依赖 |

**REQ-16 — One knowledge owner.** 新增独立的源知识 schema、持久化和协调模块，管理应用本地用户目录内的知识记录、证据与查询索引。项目只携带必要引用及冻结结果，不复制一份可独立修改的“当前知识”。不同应用用户目录默认隔离，不扫描其他 Codex session 或用户目录获取答案。

| Concern | Existing owner / proposed boundary |
| --- | --- |
| 源知识领域、修订、证据合同 | 新增聚焦的共享 schema；复用现有 rectangle/track 校验 |
| 内容匹配、原子持久化、冲突与清理 | 新增主进程 knowledge store；复用现有指纹、文件安全能力，不放进 UI 或大型 controller |
| 运行内复用、刷新和修订传播 | 新增小型协调模块，由 [agent-controller.ts](../src/main/agent-controller.ts)、[agent-runner.ts](../src/main/agent-runner.ts) 调用 |
| 原图识别与跟随 | [source-sticker-recognition.ts](../src/main/source-sticker-recognition.ts)、[collaborative-cover.ts](../src/main/collaborative-cover.ts)、[automatic-cover-tracks.ts](../src/main/automatic-cover-tracks.ts) |
| 主管协议及修正结果 | [supervisor-protocol.ts](../src/main/supervisor-protocol.ts)、[supervised-preview.ts](../src/main/supervised-preview.ts)；分别返回源事实与模板结果 |
| 证据抽取与持久交接 | [supervisor-evidence.ts](../src/main/supervisor-evidence.ts) 提供抽取，knowledge store 在临时清理前分别保存成功修订证据和已成立的反证 |
| 图层生成及补角 | [agent-template-preparation.ts](../src/main/agent-template-preparation.ts)、[automatic-corner-layout.ts](../src/main/automatic-corner-layout.ts) |
| 冻结、版本迁移、历史任务 | [domain.ts](../src/main/domain.ts)、[state-migrations.ts](../src/main/state-migrations.ts)、[store.ts](../src/main/store.ts) |
| 预览、正式导出、重试 | 原 [queue.ts](../src/main/queue.ts)、[compiler.ts](../src/main/compiler.ts)、[artifact.ts](../src/main/artifact.ts) |

**REQ-17 — Integrity and compatibility.** 先写必要证据、校验摘要，再原子发布修订及索引；断电不能产生指向缺失证据的可用记录。索引可以由已校验记录重建，不能成为另一套事实 owner。临时证据路径不可直接存为永久引用。可选择只保留必要配对帧与渲染摘要，不要求永久保存整段样片 MP4。

争议及其恢复标记必须在失败/取消路径同样可恢复。若无法持久保存已成立反证或可靠的阻断标记，停止该源制作与知识复用，直至完整性恢复或明确重建；不能继续使用旧修订。未完成写入、缺失反证或无法确认是否存在争议的状态，应进入完整性错误并阻断该源，不能作为普通未命中自动绕过。实现必须保证重启后的同等阻断，不能只在内存设置标志；临时清理不能先删除唯一反证。

旧项目无知识引用时按未命中制作，旧任务照常读取和重试；受影响的项目/模板/批次 schema 通过既有迁移 owner 处理，未知版本明确拒绝。知识库的未知格式不作为命中，也不能被降级或覆盖；应保留原文件并明确报告复用不可用。复制项目到另一台机器且没有本地知识时，仅未来制作未命中；已有冻结任务不能依赖知识库才可读取。

知识与证据清理必须同步失效引用，不留下可命中的空记录。运行中绑定的修订不可被清理；已冻结任务不依赖知识证据继续重试。首次发布前必须确定本地存储配额与回收策略，不以无限增长作为默认实现；清理不调用模型、不删除源文件或成片。

# User Experience And Model Boundaries

**REQ-18 — Minimal UI.** 沿用制作页和结果进度，显示“首次检查原贴纸”“复用已核查位置”“发现变化，正在修正”“结果未保存供复用”等可理解状态。素材提供“重新检查原贴纸”操作，详细来源和失效原因折叠展示。不默认展示坐标、摘要、协议或多层审批表。

**REQ-19 — Same authority.** 原有手动展示文字、覆盖开关、前 3 秒渐隐、原视频时长/音频、素材目录、模型选择和取消边界继续有效。模型只能返回受限方案与证据请求，不能直接写知识库、批准入队、执行 shell、任意读取文件或把图片文字当指令。只发送已约定的必要抽帧与非敏感上下文；本地路径、知识文件位置和凭据不进入模型请求。

**REQ-20 — Explainable outcomes.** 每次素材制作记录命中/未命中原因、采用修订、实际识别和主管请求数、修订及预览次数、耗时、失败阶段。记录必须能分辨“复用事实后通过新样片”“首次识别后通过”“模型误拒绝”“实际画面错误”。不能仅以成片文件存在或缓存命中率宣称质量提升。

# Real-Media Validation Protocol

实现验收使用冻结的同一批源素材、手动文字、模型配置、贴纸目录与导出设置，分别运行当前无持久复用基线、首次建知识、第二批复用、主动刷新。记录每次实际配置与代码版本；自动成绩不得使用未披露的人工框或成功 session 的硬编码坐标。

素材至少覆盖：无原贴纸、已有四角贴纸、仅部分角有贴纸、贴纸出现/消失、移动或切镜、字幕/商品容易误认、短于 3 秒、不同宽高比、VFR。复用现有氨糖膏、马油、蝴蝶贴来源，冻结明确文件清单；补充确定性的生成 fixture 只用于边界验证，不能计作真实素材效果。

分别测试关闭覆盖与自动覆盖，并保留 source/output 配对帧及可播放文件。检查首次误识别是否会被缓存放大，暖运行是否还出现相同错误，主管改正后是否传播到同素材其他版本；同时检查前 2.5 秒正常展示、2.5–3 秒渐隐、后续原内容保留，短于 3 秒的视频按结尾提前渐隐。

必须分别报告漏贴纸、误认字幕/商品、重复角标、缺角、漏盖/误盖、误拒绝、成功导出比例、实际检查帧数量、人工介入、请求和渲染次数。确认第二批命中时识别阶段请求为 0；总成本使用实际用量，无法计价则报调用数/用量而非虚构金额。

验收底线：所有上述确定性合同通过；复用没有引入已检查帧中基线不存在的新重复/缺角/误盖问题；发现的源事实错误不继续在其他版本传播。样本不足或质量未改善时报告限制，不因文件检查通过就宣称已复现成功 session 的全部效果。人工完整播放与 Windows 实机验证分别列结果，未运行时写明未验证。

# Rollout And Compatibility Decisions

建议交付顺序：源知识合同与原子持久化 → 自动路径读取/发布及同素材修订传播 → 最小 UI 和回归 → 同批真实素材冷/暖对照。每一步保留当前导出队列和模板冻结机制；确认没有争议的普通缺失/不兼容知识按未命中处理，已知反证或完整性未知则阻断并报告，不能用“缓存异常”掩盖后继续导出。

实施时须同步 repository 的一处语义变化：重新生成包装仍重新创作并检查样片，但原贴纸识别允许复用精确匹配的已核查知识。此例外由本规格的身份、时域与证据门槛约束；不改变自动模式的不确定失败规则，也不放宽 `assisted` 的人工批准。

本规格不预先固定 schema 数字、存储容量或新增 public API 名称。实现开始前依据届时代码确定这些技术值，并以 executable tests 验证；不得为了满足缓存命中而放宽源身份、证据、预算或冻结合同。
