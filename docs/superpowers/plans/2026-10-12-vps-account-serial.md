# VPS Account Serial Automation

## Goal

按用户要求，同一 VPS 的自动化一次只运行一个账号 Chrome。当前账号全部上传小批次取得持久 ACCEPTED 回执后正常关闭，再处理下一个账号；清理也逐账号执行并在成功后关闭。登录资料保留。

## Scope And Owners

复用 AutomationRuntime、原 controller / ExportQueue、DouyinUploadService / Store、QianchuanAccountSettings / BrowserManager / RemoteRuntime。新增小模块只协调浏览器资源，不持有任务、队列、重试或确认权。index.ts 接入可信主进程回调；不改定时时间、UI、配置 schema 或历史账本。

## Contracts

- 原本地制作和导出并发保留，首条成片仍可立即上传，每次至多 9 条。同一远端账号跨小批次持有浏览器，直到其所有模板任务终态且成功成片均已上传。
- 首次使用账号前按当前配置核对同 VPS 的所有账号。存在未结束 READY、UNKNOWN、可能已选择文件、正在准入的意图时停止，不能关闭草稿或打开下一个账号。
- 自动关闭只允许无待处理任务，或具有持久接收证据的 ACCEPTED。不结束批次、不改结果、不清防重传屏障；普通手动关闭护栏保持。
- 每个 B 上传小批次取得持久 ACCEPTED 后，核对同批回执及原 targetId，只关闭本次自有上传页并断开 CDP，避免同账号积累已完成标签页。普通 READY、UNKNOWN 和其他页面保留。
- 账号完成后通过原正常退出路径关闭；关闭失败、取消或身份变化停止下一账号，不强杀、不建立替代 profile、不自动重试。
- 清理关闭发生在账号映射 edit 锁释放之后。非 CLEARED 清理结果保留窗口并短路后续账号；原清理删除权限和未知结果门不变。
- 账号持有期间拒绝手动打开其他账号及后台计划预读，防止并行旁路。错误保留原页面并释放内存中的资源协调状态，持久保护仍由 Store 独占。
- 本机直连及 A 路线不自动关闭 Chrome；本变更只管理 B 路线。

## Implementation

1. 添加浏览器协调模块与五账号、保护草稿、关闭失败测试。
2. 原服务按账号分组上传、串行清理；原流式观察器锁定当前远端账号并通知账号完成。接线到当前自动化运行。
3. 验证集成顺序、跨小批次持有、异常停止、原取消和永久屏障；完成项目 Harness、AOCI 与风险门。空闲时进行真实 VPS 开关与资源观察，不为验收重传历史素材。

## Acceptance And Self Review

五账号受控测试同时打开数上限为 1，顺序为打开 A、完成并关闭 A、打开 B；同账号两次上传间不关闭。READY / UNKNOWN 和关闭失败阻止下一账号。实际 VPS 仅验证当前已有账号开关及内存观察，五账号真实负载和平台审核不由假服务证明。

用户已授权按账号关闭，无需追加确认。闭环以当前源码、持久回执和原浏览器生命周期为准；不复用会全局清权限的 closeBatch，不在清理 edit 内嵌套 controlBrowser。现有其他会话的定时和 UI 改动保留。
