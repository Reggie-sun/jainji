## Goal

用户选择明确的店铺/广告账户、商品和推广计划，在原 JIANJI 制作流程产出视频；软件完成经授权的素材上传和计划操作，并把实际消耗、成交及素材表现关联回本地成片。

最小完整闭环是：**确认账户与商品 → 制作成片 → 平台接收素材 → 创建或绑定真实计划 → 在明确授权内设置 ROI/预算及投放状态 → 回读设置和状态 → 采集效果 → 追溯到原成片。** 每一步都有可核对的平台身份和结果，不能以页面已复刻、接口名称已找到或测试通过代替真实接入。

## Product Decisions

1. **首版面向商品全域推广。** 首先覆盖当前真实在用的商品计划和投放模式；直播全域、其他广告产品及未验证模式独立标为未接入，不做通用万能建计划器。
2. **默认使用正常千川浏览器会话直接接入。** 当前用户无官方 API；不得要求先申请 API 才能使用已可复现的能力。已有本机、本机经 VPS 出口、VPS 浏览器模式沿原 owner 处理，不能为接入而复制登录资料。
3. **千管家是可选只读 provider。** 保留其已实测的目录和汇总作为辅助；独立接入的核心验收在不连接千管家的情况下进行。供应商断开、试用到期不能阻断已独立接通的千川功能。
4. **能力按账户、推广模式和动作分别启用。** “已连接”只证明连接；计划读取成功不自动启用创建、调价或上传。未接通的功能显示具体原因，不能用可点击的空按钮或演示数据代替。
5. **先交付手动可控的真实闭环。** 基础创建、调整和效果回读属于核心必交；批量提效排在其后。自动调价、自动扩预算不属于首轮上线条件，默认关闭。
6. **首版保留现有六个稳定账号槽。** 多账户/多店铺按平台身份建立关联，不把槽位名称当店铺身份。任意数量账号、无上限店铺管理需要后续 schema 迁移，不顺带改造。

### F01 — Accounts And Shops

- 复用正常登录会话和现有账号管理入口，显示保存的浏览器锚点、当前网页子账户和真实广告主 ID；三者不能相互冒充。登录失效、验证码或无权限时给出正常登录入口并停止对应请求。
- `shopId`、广告主、抖音号和商品关系只能由平台明确数据或经核验的用户选择建立。没有店铺身份时显示“店铺未识别”，仍可使用已核验的账户功能，但不能宣称已完成多店铺管理。
- 目录按账户隔离；切换账户后，旧请求不得回写新账户页面。当前选择只影响下一次查询或新操作，不迁移历史批次、运行中任务和冻结授权。
- 第一次完整验收至少使用两个不同的已授权广告账户。多店铺验收另需两个可核验店铺身份；只有两个 advertiser ID 不够。

### F02 — Products And Plan Reads

- 展示真实可选商品、商品 ID、对应推广范围、已有计划 ID/名称、计划状态、预算类型/值及 ROI 目标；缺失字段显示未知，不猜测默认值。
- 区分“平台当前值”“用户编辑草稿”和“上次观察”。草稿不得显示为已生效设置；实际操作前必须重新读取目标和可编辑范围。
- 商品与账户、抖音号及推广模式的资格在主进程核验。平台未返回明确资格或完整必填字段时，禁止创建，给出缺项；不能用千管家的建议值作为平台资格。
- 历史目录遵守原展示缓存合同；能展示旧目录不等于有权按旧目录创建、上传或修改计划。

### F03 — Upload And Material Management

- 复用原制作、ArtifactVerifier、上传 service/store 和文件选择/确认屏障。上传对象必须是已验证成片，绑定文件身份、账户、计划和原任务；不重写原视频。
- 保留现有逐组选择和整批确认语义；新功能不放宽 READY、ACCEPTED、UNKNOWN 和防重传边界。平台接收、审核通过、已加入计划和正在投放分别展示。
- 查询素材目录、上传时间及平台确实提供的审核/使用状态；未提供的状态标未知。记录精确 `platformVideoId` 与 `materialId`，不能拿文件名或素材名代替。
- 为“新建计划前先上传素材”调查独立素材库上传能力。若现有上传必须绑定已有计划，不得伪造计划、借用其他计划暂存或绕过原授权；该模式在平台能力验证完成前保持不可用。
- 本地移除关联不等于删除平台素材。平台删除继续使用原清理合同及明确删除范围，不随上传、效果差或计划暂停自动触发。

### F04 — Create Or Bind Product-wide Plans

- 在既有“计划与数据”入口增加明确的创建/绑定工作流：选择已核验账户、商品、推广模式、已接收素材、预算和 ROI 目标，形成草稿并执行只读预检。
- 参数范围、必填项和枚举来自实际平台能力。必须补齐当前目标模式的真实表单与网络证据，不能根据 `batchSave` 等名字拼请求。平台不支持的组合明确拒绝。
- 默认目标为**创建后暂停**；只有平台能保证该语义时才提供此选项。若创建本身可能立即产生花费，则按“创建并可能启用”展示影响并要求相应投放授权，不能悄悄创建后再尝试暂停。
- 单次创建只允许一个冻结草稿和一次提交；返回新计划 ID 后独立回读账户、商品、关键参数和状态。没有可归属的计划 ID 或回读不一致时标结果未知，不重发创建。
- 加入已有计划要证明素材确实进入该计划，保持原上传确认 owner 唯一。操作成功只证明加入或创建，不证明已审核、已投放或已经产生成交。

### F05 — ROI, Budget And Delivery State

- 支持先读当前 ROI 目标、预算值/类型及投放状态，再编辑单计划草稿，展示前值、目标值、差额及影响范围。ROI 目标与效果报表中的支付 ROI/净成交 ROI 分开命名。
- 主进程检查账号、计划、当前模式、允许范围、有限授权和预算额度。前值、版本或编辑权限变化时必须重新预检，不把旧批准套到新目标。
- 预算增加、减少、ROI 修改、启用、暂停均为不同动作；资格分别验证。未经授权不把修改 ROI 顺带变成扩预算或启用计划，不能自动切换推广模式。
- 提交后独立回读相应平台值和状态，再记录确认结果；HTTP 成功、弹窗消失和按钮提示不能单独证明生效。失败时保留草稿和安全原因，不自动重试或自动回滚。
- 批量修改属于 F09；首轮先把单计划的前值、授权、一次执行和回读做实。

### F06 — Reports And Historical Snapshots

- 账户、计划、素材分层查询，至少覆盖消耗、支付成交金额、支付订单数和平台给定的 ROI。每次保留数据来源、身份、北京时间统计窗口、采集时间、原始单位/币种、指标定义及完整性。
- 平台支付/含券/净成交/退款口径不能混用；未取得的指标为空并说明原因。没有同口径成交和消耗时不计算 ROI；同口径汇总按平台定义计算或使用其汇总值，不相加或简单平均 ROI。
- 分页共享同一冻结窗口，重复、缺页、总数或身份漂移拒绝完整快照。允许保留失败进度，但不能把部分数据发布成完整报表，也不能把查询失败变成零消耗。
- 复用现有单次最多 31 天的查询边界；效果采集沿原 2000 行、180 秒边界。更大范围属于 F09 的有界分段采集，不在首轮静默放大限制。
- 首版按用户手动刷新保存必要的归一化快照，原子写入应用私有目录，读取不触发广告操作。新增快照只有一个 owner，不拿展示缓存或上传账本当报表库；原始大响应、临时播放 URL 和凭据不落库。

### F07 — Production-to-effect Attribution

- 用户能从原成片查看所属制作批次、上传任务、冻结广告主/计划、平台视频 ID、对应素材、接收/审核/投放观察及统计窗口；也能从素材效果返回原作品。
- 继续使用原 ACCEPTED 证据中的 `platformVideoId` 与平台报表 `VideoId` 精确关联；`materialId` 独立保留。一个视频对应多个素材时全部保留，不能随意选第一条或跨计划合并为一次投放。
- 同内容别名或复用成片保留原任务关系；汇总指标按明确的统计行键去重，避免同一素材的消耗因多个本地记录重复累计。
- 未发现指标、未投放、未接收、查询不完整和证据无效是不同状态。没有视频 ID 的历史记录保留为未关联，不以文件名、顺序或金额猜测。
- 支持按账户、计划、商品、本地制作批次和日期筛选、排序与 CSV 导出。效果排序仅为观察，不自动触发删除、重传、调价或停投。

### F08 — Authorization, Audit And Stop

真实写操作必须先满足下列合同；本规格不为用户填写任何真实账号、预算或授权额度。

| 授权内容 | 必需约束 |
| --- | --- |
| 对象 | 精确账户、计划或创建草稿；涉及商品、素材时同时绑定这些身份 |
| 动作 | 明确创建、加入素材、ROI、预算、启用或暂停，禁止通配所有写权限 |
| 金额 | 写明币种、预算类型、允许的目标预算上限和本次可增加预算总额；未填写不视为无限 |
| 次数与期限 | 有限动作数、有效期和本批预算；跨重启不恢复未完成执行权 |
| 前提 | 当前值/版本、配置和数据来源绑定；对象或前值变化使授权失效 |
| 审计 | 操作 ID、请求摘要、前值/目标值、授权边界、提交时间、可安全记录的请求 ID、平台对象 ID及回读证据 |

- 金额以明确单位和精确十进制表示；不能用浮点误差越过上限。并发操作共享原子额度预留，未知结果的预留不自动释放。实际广告消费可能延迟且包含已有计划支出，不能声称本地预算限制保证平台实际总消耗绝不超过某数。
- 写入意图必须在平台提交前持久化；持久化失败则零提交。已提交但结果不明时锁存 UNKNOWN，只允许只读核查，不因关闭应用、结束本地批次或更换 provider 清除历史屏障。
- UNKNOWN 保护按原广告主、计划及受影响资源匹配；换操作 ID、账号槽位或重新创建草稿不能绕过。只有可核验的未发送、明确拒绝或已确认结果才能按对应规则结清额度预留，历史意图与证据保留。
- 新投放变更使用独立职责的最小操作审计记录，不能把广告 UNKNOWN 写成上传 UNKNOWN 或修改原上传结果。它不是第二生产/上传队列，也不获得原队列的文件选择和确认能力。
- 用户可立即停止新的本地自动动作并取消可取消的请求。**本地停止不等于平台暂停**；平台暂停需对已获管理授权的明确计划执行独立操作并回读。暂停结果未知时要显示平台可能仍在投放。
- 禁止用自动补偿写入掩盖未知结果；任何恢复执行都需先核清原结果及仍有效的授权，原上传历史继续遵守其唯一 owner 的恢复规则。

## Integration And Evidence Contract

### Providers And Capability Admission

| 路线 | 目标用途 | 接入条件与限制 |
| --- | --- | --- |
| 直接千川浏览器 | 首选独立读写路线 | 正常登录、账户权限、固定配方、可核验网页身份；每个写能力须单独准入 |
| 自有官方 API | 后续可选 provider | 自有应用获权及正常 OAuth；不能借用千管家服务端 token，也不作为首版前置条件 |
| 千管家中台 | 已实测的目录/汇总与对照 | 正常客户会话及权益；首版仅固定只读能力，不作为独立闭环或写操作的备用通道 |

每个能力记录 `未调查 / 静态定位 / 隔离验证 / 真实只读验证 / 真实写入及回读验证 / 当前不可用` 和证据时间。连接失效与历史证据分开；过往成功不证明当前会话仍可执行。不同账户和推广模式不能共用一张未经范围绑定的“全部可用”标志。

写配方准入必须包含：固定 method/path 或可核验页面动作、完整参数与响应校验、实际角色/对象范围、提交点和取消边界、平台错误、结果核查方式及真实受控验收。能正常打开页面或返回 code=0 不足以准入。

同一操作冻结 provider、身份和请求摘要。失败或未知后不得自动改走官方 API、千管家或另一个浏览器再提交。普通登录、权限、付费和验证码均走正常用户流程，不绕过，不提取第三方服务端秘密。

### Identity And Data Boundaries

平台 ID 全程保留精确字符串。稳定账号槽、浏览器锚点、当前子账户、`shopId`、`advertiserId`、`awemeId`、`productId`、`adId`、`platformVideoId` 和 `materialId` 各有含义，不得互换；名称只用于展示。

投放写操作必须接入既有账户/浏览器资源保护，与同资源的账号切换、浏览器生命周期、上传及清理互斥。原 READY/UNKNOWN 上传页保持受保护；查询或投放适配器只使用经验证的自有页面，不导航、刷新或关闭原用户任务页。新的共享互斥需由唯一资源 owner 管理，不以各服务分别检查一个 busy 布尔值代替。

关系最少覆盖：原项目/制作批次/成片任务及文件摘要 → 原上传任务与接收证据 → 平台视频/素材 → 广告主和计划 → 带口径与时窗的指标。缺一段则明确未关联，不新建推测关系。

登录凭据留在原浏览器或主进程私有凭据 owner。renderer、项目、模板、导出 CSV、审计日志和规格证据均不得包含 Cookie、token、私钥、原始认证头或带临时授权的 URL。

## User Experience

- “投放工作台”展示真实来源、统计窗口、采集时间及账户范围；供应商用户汇总与单账户数据分开。缺数据用未知/未读取，不填假零或示例趋势。
- “账号与计划”解决接入、正常登录、当前账户核验及店铺关系；“计划与数据”完成商品/计划查询、创建和参数操作；“制作与效果”承接成片追溯、效果筛选和原制作入口。
- 写入前展示明确目标、当前值、修改值、金额影响和授权范围；提交中禁重复点击。未知结果保留操作记录和只读核查入口，不展示误导性的“一键重试”。
- 错误在当前操作附近说明可采取的正常动作；失败保留草稿和已有只读结果，不自动换账号、重置其他页面或关闭用户浏览器。
- 桌面和现有窄窗口可操作，关键确认信息和操作按钮不能被横向裁掉。继续围绕正常目录的 `make frontend` 验收，不要求用户改用另一份临时资料目录。

## Delivery Stages

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| M0 | 能力核验与证据目录 | 明确目标账户/模式的商品、计划、素材读写可用性及缺项；未验证的写配方保持禁用 |
| M1 | 独立读取与素材链路 | F01–F03 的可执行部分、F06/F07；断开千管家仍可读，原真实成片接收后能回读并关联；仅标“素材与只读接入” |
| M2 | 单计划受控写入 | F04/F05/F08：真实创建/绑定、ROI 和预算修改、暂停/启用逐项受控验收；任何必需项缺少平台能力则明确阻断该项 |
| M3 | 完整业务验收 | 所有 P0 完成，完成下表真实闭环及多账户/店铺隔离；才可称“真实投放接入完成” |
| M4 | 批量与分析提效 | F09：逐项结果、聚合预算限制、历史对账和日报；不改变 M3 的授权边界 |
| M5 | 有限规则自动化 | F10：先观察建议，再基于有时限、对象/动作/金额/次数明确的规则授权执行；默认关闭 |

F09 跨账户批量不是跨账户原子事务：逐项预检与审计，前项未知时停止相关写入，不盲目撤回已确认结果。历史采集只合并同口径、无重复的完整分段；失败标示缺段。规则自动化必须有数据完整性、样本门槛、冷却、单日动作数及累计预算增加上限；这些参数由用户明示，不凭 AI 猜测商业阈值。规则停止或重启不补跑历史触发。

## Acceptance Matrix

| ID | 必需场景 | 可验收证据 |
| --- | --- | --- |
| A01 | 无千管家连接、无自有官方 API | 正常千川会话能读取已授权账户的商品/计划/素材及指标；真实响应与平台界面核对 |
| A02 | 原队列生产上传 | 一条本轮已验证成片沿原 owner 上传，具有账户/计划/文件绑定的真实接收回执，并在平台回读到相同视频 ID；不以 READY 代替 |
| A03 | 商品全域计划创建与绑定 | 明确授权后一次提交，独立回读同账户、商品、素材、预算、ROI 和期望状态；若平台缺某项则该能力未验收 |
| A04 | ROI、预算、暂停和启用 | 每种动作各有前值、冻结授权、一次提交记录与独立回读；真实测试额度/对象由用户事先明确，未提供时保持未评估 |
| A05 | 结果未知与重启 | 隔离故障注入证明提交后断网/超时/退出不会再次提交、自动切 provider、释放未知额度或清除屏障；真实平台不人为制造未知花费 |
| A06 | 金额与并发限制 | 隔离验证拒绝超限、过期授权、前值漂移和并发越额，平台调用计数为零；测试不消耗真实预算 |
| A07 | 多账户及真实多店铺 | 至少两个授权账户，验证请求、指标、成片和操作不串号；另有两家可核验店铺的独立流程才授多店铺验收 |
| A08 | 效果回读与口径 | 同窗口对账消耗/成交/订单/ROI；新接收视频正确关联，复用别名不重复累加，未投放或归因延迟不伪造零值 |
| A09 | 取消与陈旧数据 | fixture/浏览器证明取消、隐藏、换号、配置变化隔离迟到结果；历史展示记录不能授予写权限 |
| A10 | 原功能兼容 | 原制作、批量、追加、自动化和上传历史相关回归通过；冻结目标、UNKNOWN、防重传及共享浏览器保护保持 |
| A11 | 用户可见与平台证明分层 | Chrome 集成测试证明真实操作入口；当前源码 Harness/completion 通过；另外记录真实平台响应、结果回读和用户可核对画面 |

真实验收先做只读核对；涉及花费或参数变化时，仅在用户事先明确的账号、计划、额度、次数和时间内逐项进行。没有测试账户/授权或平台能力时记为 `NOT_EVALUATED` 或具体阻断，不能用 mock PASS 补齐。

## Non-goals

首版不建设独立云端大数据中台、跨租户 SaaS、消息队列集群、自动生成广告文案、AI 自主调价或无限账号管理；不更改视频生产内容规则；不复制千管家专有实现、绕过会员/登录或恢复第三方服务端凭据；不承诺平台实时归因、投放收益或绝对消费上限。

## Spec Self-review

- 核心目标包含真实创建/绑定和 ROI/预算操作，不能以当前两项供应商只读接口或历史素材关联替代全部交付。
- 当前用户无官方 API 的事实已纳入默认路线；千管家停服/过期不会成为独立模块的设计前提，未证明的浏览器写能力仍必须技术验证。
- 新财务写入与原上传确认分工明确；所有未知结果、冻结目标、历史记录及资源保护保持，不设计第二生产/上传队列。
- 新建计划可能立即花费、素材上传可能依赖旧计划、真实店铺身份尚缺、指标口径/分页及取消边界均列为显式验收问题，没有把未验证能力当成事实。
- 本轮仅新增此规格，不修改并发业务文件、不运行真实平台操作；实现计划和工程验证应在后续明确实施任务中按当前源码与合同生成。
