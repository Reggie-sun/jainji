# Qianchuan Durable Display Cache

## Goal

子账户与计划成功读取后持久保存，五分钟后或 Chrome/网络连接失败时仍可显示和编辑已有目录草稿。覆盖普通制作、批量制作、清理计划及所有上传方式，包括本机上传、本机上传 · VPS 出口和 VPS 上传。

## Accepted Delta

当前用户明确要求长期缓存且覆盖所有模式。此增量仅替换展示入口的“过期/读取失败即清空目录”行为；此前目录核对失败禁用计划选择的要求，对带 `displayCache: true` 的历史展示投影改为明确标示上次记录。未选择该增量的旧 API 及实际制作、上传、切换和清理继续使用原实时验证。

## Contracts

- `DouyinUploadService` 保持原生产 owner；新 `QianchuanDisplayCatalogs` 仅协调展示请求和持久化目录，实时读取回调复用原 `catalogPlans` 与 `listSubaccounts`。
- 请求可选 `displayCache: true`。计划展示响应返回 `{ plans, account?, cache }`；子账户目录可附加 `cache`。不请求该字段的原响应形状保持不变。
- `cache` 区分 `source: live/cache`，携带 `readAt`、`stale` 及可选 `refreshFailed`。来自缓存的数据始终是历史投影，五分钟只影响 `stale` 标记，不删除、不强制连 Chrome。
- 缓存按保存账号锚点、产品、目录类型及计划所属 advertiser ID 隔离；当前网页与保存账号计划不混用。传输方式变化可复用同锚点的历史记录，并标记配置 digest 不同的记录为旧记录。
- 成功的显式刷新才替换缓存；刷新失败返回原记录并标示失败。首次无记录仍须真实读取。缓存命中不打开浏览器、建立 SSH 隧道或发送平台请求。
- 使用应用私有目录与原子 JSON 持久化；每条记录至多 4 MiB，严格 schema、路径/权限检查，非法或跨账号记录视为未命中。写入失败不破坏此前记录，也不使已读取目录失败；展示响应标示未持久化。
- 缓存不含视频、本地浏览器路径、Cookie、token 或凭据，只保存目录、账户投影、配置 digest 和读取时间。

## Invariants

历史投影可以形成下一轮显式选择草稿；不能成为账号已核对、READY、切换批准、冻结授权、上传成功或删除证据。生产准入、文件选择前目标核对、清理前计划重验和真实切换不调用展示缓存。UNKNOWN、不重发、冻结目标及原队列保持。

## Acceptance

1. 成功读取后关闭原 Chrome，等待超过五分钟或重启 service，目录与计划仍可恢复且不触发实时 reader。
2. 所有上传方式共用此行为；保存账号和网页子账户计划按各自身份隔离，传输模式不会清空已有历史投影。
3. 手动刷新失败仍保留列表及原显式选择；成功刷新可移除失效计划并清理相应选择。
4. 缓存只更新在完整 schema 与身份检查成功后；跨锚点/子账户、损坏文件或不安全路径不复用。
5. 历史计划仍须通过原生产/清理实时验证；连接失败或目标改变时不创建错误上传授权或执行删除。

## Self-Review

授权来自当前用户的缓存修正与所有模式要求。主要风险是混淆历史显示与在线授权；通过 opt-in API、显式状态、严格身份绑定及不修改生产 reader 解决。此增量不授权切换上传方式、放宽平台/权限资格或改变旧任务。工程验证与真实 VPS 网络耗时分开报告。
