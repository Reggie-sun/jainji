# Export Speed Regression Investigation

## Scope

2026-10-05 用户反馈制作比之前慢。本轮保留正在执行的 530 条跨模板制作、原上传页面和 UNKNOWN 屏障；不取消、重排或重传，不改变冻结画质、帧率、图层、NVENC 准入和并发设置。

## Evidence

同项目历史任务存在速度退化：一组约 108 秒素材中，8 张 PNG 加文字的任务，中位耗时从 2026-10-02 的 20.96 秒升至 2026-10-05 的 49.56 秒；另一组 4 张 PNG 加文字从 2026-10-04 的 28.48 秒升至 64.28 秒。上述比较控制了项目、时长和配置类别，尚未控制每项源字节、贴纸字节、主机负载和软件版本，因此证明退化现象，不能单独归因。

同批其他模板的耗时持平或改善。现场使用 NVENC，配置为 6 路导出、8 路分析、20 个线程；观察到 2–3 个编码进程及短暂验证，排队原因是 NVENC 启动准入，没有验证积压或显存等待的证据。两组慢模板执行时间与本机多轮媒体回归测试重叠；这是资源争用假设，尚未通过控制实验确证。

## Software Change

[DouyinUploadService.status](../src/main/douyin-upload-service.ts) 原先分别为暂停判断、任务、批次及阻塞消息调用 `store.tasks()`，每次都深拷贝整个上传账本。正常路径可产生 4 次完整克隆，跨项目 UNKNOWN 暂停路径可产生 6 次。

现在每次同步状态计算只取得一份新鲜任务快照，再派生各个投影并传给暂停消息。没有跨调用缓存；对外结果仍为隔离副本，不改变持久化或上传准入。其他调用者保持原默认读取方式。

## Verification

[上传服务测试](../tests/douyin-upload-service.test.ts) 新增两项回归：每次状态计算只读一次完整任务集合、返回副本不可污染账本、后续状态不缓存，以及其他项目 UNKNOWN 对当前账号的暂停消息和禁止重传仍保留。修复前分别观察到 4 和 6 次读取；修复后均为 1 次。完整服务测试 80 项通过，全库 typecheck 复查通过。

本地只读基准将同一份 10,344,637 字节、2502 条任务的账本仅载入隔离内存，交替运行修复前后状态计算，各 9 次。正常路径中位耗时从 81.54 毫秒降至 22.20 毫秒；完整公开状态 JSON 相等。没有连接账号、写入生产账本或执行浏览器动作。基准仅证明此状态投影的成本变化，不能推导视频导出提升倍率。

脱敏运行证据保存在忽略目录 `.agent/harness/runs/20261005-export-speed/`，包括 `status-comparison.json`、red/green 日志和类型检查结果；不提交用户账本、媒体路径和私有任务身份。交付另外执行 owned scope Harness 与 receipt verify，以当前回执为准。

## Runtime Boundary

原主进程保留到制作、导出及上传全部空闲。2026-10-05 18:14 的只读观察中，530 条导出全部完成，旧 preload 仍未提供计划取消桥接，状态读取约 72–75 毫秒；此时新主进程代码尚未生效，不能据此验收修复后的实际制作吞吐。

FFmpeg 启动信号与 GIF 探测的[上游研究](research/2026-10-05-nvenc-startup-progress.md)未证明修改 NVENC 释放条件可以提升这批吞吐，本轮不据此更改准入规则。没有匹配样本的新主进程制作数据前，整体速度恢复仍未评估。

## Review And Record

实现边界为同步只读状态投影，现有项目过滤和 UNKNOWN 账号屏障谓词保持；不修改持久状态、选择文件、确认、授权或重试。Risk Gate 在项目验证后的稳定快照上记录；本记录不代替回执或真实吞吐验收。

仓库未声明专用 session-record/capture Skill。本轮具有 durable value，采用此诊断记录与脱敏运行回执保存证据，不写 `.agent/bug-memory/` 或外部 Codex memory。
