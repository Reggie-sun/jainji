# Qianchuan Browser Subaccounts

## Behavior

普通制作与批量制作默认通过已验证的原 Chrome 连接读取子账户目录、显式切换和当前账户计划。此默认方式不要求安装或连接扩展。本机、代理以及 VPS 均从保存账号的原 Chrome 资料目录解析连接；当前网页子账户独立于保存锚点，新增账户无需登记代码中的 ID。子账户选择只影响下一轮，历史批次保持原账号与计划。

界面按保存账号、子账户、上传计划的顺序操作。先独立读取子账户目录并确认当前身份，再读取该子账户的计划；计划读取失败后仍可刷新目录或选择其他子账户。目录失败时禁用计划选择，显式刷新恢复目录后再读取计划，避免两者互相等待。

网页初次打开可以是主账户。目录使用 REA 确认的 `GET /ad/api/v1/account/user-list` 和 `GET /ad/api/v1/account/user/info`，完整核对分页及当前身份，不根据保存锚点推断当前子账户。用户选择后原网页至多导航一次，再核对相同真实 target 的新文档、姓名与 ID。计划复用原 `readQianchuanPlans` 的后台只读页；完成或取消先清理该自有页再返回。原文件上传、清理及确认继续使用既有 owner 和安全边界。

## Connection

使用账号设置打开各账号的原浏览器，保持千川页面已登录；再在制作界面刷新子账户并选择目标。保存的端口只是配置，连接必须另经原 profile、PID/starttime、Chrome 持有的 loopback socket、ActivePort 和实际 browserPath 核验。不会因失败改连其他 Chrome、复制登录资料或重写保存锚点。

Chrome 正在显示其他标签页时，唯一的合格千川后台页也可读取目录并切换子账户，不需要先激活它；有多个后台千川页且没有明确可见页时拒绝猜选。此目录行为不改变原上传或清理对当前页面的检查。

目录读取同时支持带唯一 `aavid` 的千川根路径 `/` 页面，包括旧扩展切换后留下的入口；仍须通过网页 DOM 账户、原文档及浏览器 context 核对。该兼容入口仅用于目录会话，不扩大原上传或清理的页面范围。

VPS 使用固定 `browser-profile` RPC 读取同样的进程与监听证明，经过原严格 SSH 通道建立 loopback 转发；此 RPC 不注册 native host、不启动 Chrome、不导航网页。远端需要包含该接口的 worker。主机指纹、非交互鉴权和主体绑定保持；不开放公网调试监听。远端浏览器关闭时先从账号设置打开原窗口，失效通道通过已有“重新连接”恢复，不自动切回本机。

已有扩展实现保留为明确注入的适配器，共用签名及目录完整性 owner；不会在 CDP、扩展与网页菜单之间按异常自动降级。开发资源仍在 `resources/qianchuan-extension/`，随应用和 worker 构建提供，默认账户读取无需逐资料加载它。

## Safety And Recovery

平台 Cookie 和 CSRF 仅在 Chrome 使用；简辑只收到账户与计划投影。CDP 使用真实字符串 target ID 与同文档持续存在的隔离上下文标记，不伪装成扩展数字 tab ID。分页缺失、ID 精度丢失、账户或文档漂移以及未知导航结果拒绝，不自动重发切换或回切。待确认和结果未知的原上传任务继续阻止切换原浏览器。

默认读取要求已核验的调试连接。共用资料根目录出现其他 Chrome profile 时仍拒绝连接，不将一个进程的端口冒充为特定 profile 中页面的证明。不会删除多余 profile 或改动原绑定来绕过检查。新一轮只读 metadata 请求可以重建已终止的 SSH 通信，但不重发失败操作、不恢复旧上传租约或冻结授权；现有未终止的连接与主体变化仍拒绝。显式恢复 VPS 连接也不自动继续旧任务。

## Verification Boundary

协议与隔离 Chrome fixture 只证明软件接线，不等于真实账户权限、VPS 安装状态或平台上传成功。本轮实际运行、剩余阻断以及远端提交身份需以交付记录为准。
