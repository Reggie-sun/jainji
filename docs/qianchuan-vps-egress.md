# Fixed VPS Egress

## Scope

Linux `make frontend` 的千川账号支持可选固定 VPS 出口。本机 Chrome、本机视频和原上传队列保持不变。主体代号只用于配置分组，不是身份证信息，也不保证平台不关联账号。

## Setup

每台 VPS 需要可用的 OpenSSH 服务、固定公网 IPv4 和允许 TCP forwarding 的 SSH 用户。在本机为三个主体分别配置 `~/.ssh/config`，例如：

```sshconfig
Host shop-one
    HostName <VPS 公网地址>
    User <SSH 用户名>
    IdentityFile ~/.ssh/shop-one
    IdentitiesOnly yes
```

其余两台使用独立别名，例如 `shop-two`、`shop-three`。私钥仅由 OpenSSH 使用；不要上传到 Jianji、项目或聊天。先人工核实服务器主机指纹并保存到 `known_hosts`，确保 `ssh -o BatchMode=yes -o StrictHostKeyChecking=yes shop-one true` 能成功。程序不会自动接受新指纹、弹出密码框或运行远程安装命令。默认使用 `/usr/bin/ssh`、`/usr/bin/curl`，并要求 VPS 允许 SSH 动态转发。

进入“千川 → 账号与计划”，点选账号，选择“本机上传 · VPS 出口”（A：本机浏览器）并点击“保存账号”即可。已有 VPS 连接无需重新填写；首次配置展开“高级连接设置”。选择“本机上传”会解除该账号出口设置；选择“VPS 上传”使用 [远端浏览器](qianchuan-remote-browser.md)。仅选择不保存或启动上传，保存结果显示在账号区域。

| Field | Meaning |
| --- | --- |
| 主体代号 | 自定营业执照代号，同主体账号复用同一组设置 |
| SSH 主机别名 | 如 `shop-one`，引用本机既有 SSH 配置 |
| 预期出口 IPv4 | 经 VPS 实际出网观察确认的固定公网 IPv4，可能不同于 SSH 入口地址 |
| 本地连接端口 | 如 `19381`、`19382`、`19383`；不同主体必须不同 |

首次保存不连接平台。保存后点击“打开账号浏览器 / 登录”，程序建立 SSH SOCKS 隧道，先经隧道访问固定 HTTPS IP 服务，再核对 Chrome 实际启动参数及浏览器后台探测页的出口。成功后打开千川；首次登录和验证码仍由用户处理。新制作自动选择已绑定出口，不需要手动切代理。

## Failure And Recovery

- 检查服务固定为 `https://checkip.amazonaws.com`；探测带有限超时，不带平台凭据。该服务不可达或响应无效时撤销自动化权限并保留失败屏障，但不关闭仍由程序持有的 SSH 隧道，原浏览器继续使用同一 VPS。明确重连后复用该隧道重新核验，旧任务权限不恢复；IP 确实不符或 SSH 真正退出则停止该隧道。不换检测服务或直连，检测不可用期间不会授予自动化权限。
- Chrome 固定使用一个 SOCKS 代理，禁用 QUIC、非代理 WebRTC 和扩展，外部 DNS 通过代理解析；无 DIRECT fallback。程序不更改全系统代理。
- 隧道断开时停止该上传连接。恢复后点击“重连固定出口”只恢复同配置出口并重新校验，仍存活的自有隧道不重建；不会启动上传、重传旧文件、修改未知结果或点击千川“确定”。
- 程序正常退出会停止自己启动的 SSH 子进程，并保留原账号 Chrome。Linux `make frontend` 下由现有开发启动器持有同一个出口 runtime，Electron 热重启只释放旧进程的上传连接权限，不断开 SSH；新进程通过私有 parent IPC 重新核验同配置隧道和浏览器实际出口，真实断线的失败屏障也跨热重启保留。启动器退出才关闭其 SSH；IPC 不可用时停止自动化，不回退到本机另建隧道，也不接管未知端口。
- 完整退出后再次启动时，仅对仍在运行、且已保存目录绑定或应用专用目录、唯一连接和代理参数均匹配的本机窗口重建同配置隧道，再校验隧道与浏览器实际出口；不打开、关闭或刷新原页面，不恢复旧上传。未打开的账号和远端浏览器不自动连接。恢复失败保留账号配置和失败屏障，需点击“重连固定出口”，不自动反复尝试。
- 异常退出可能留下监听者，下一次发现端口占用会阻断，不接管或自动杀死未知进程。需核实该进程归属后人工处理。
- 保存账号时程序检查受保护任务，再正常关闭相关空闲浏览器并应用设置；不需要手动关闭或勾选整组。同主体在原出口上的 A/B 切换由后端计算全部成员，一次保存；网页未保存内容可能丢失，登录资料保留。旧批次及子账户有待处理、待确认或结果未知时，原窗口和设置保留，并在保存按钮附近显示原因，不自动结束任务。关闭失败可能已有部分空闲窗口关闭，但整组设置不部分写入。
- 同主体配置仍须一致，不同主体不能复用别名、端口或 IP。A/B 整组切换只改变上传方式，不迁移主体或 IP。导入和启动恢复保持原闭窗检查，不自动关闭浏览器；更换整组出口仍需单独处理原绑定。
- 账号编辑区“查看未结束上传”包含旧项目相关批次，不受本次制作范围限制。核查原上传页面后逐批明确确认“结束本批本地上传”；视频、原结果与防重传屏障保留，剩余上传资格永久取消。查看或取消不写入，结束后需再次保存所选上传方式；程序不自动结束、确认或重传。
- 旧配置没有 `egress` 时保持原行为。已有批次冻结原出口；重复检测仍以视频和广告账户/计划为准，换出口不产生重传许可。读取或保存配置结果不明仍失败关闭。

## Verification Limits

本地测试覆盖路由校验、浏览器实际 IP 响应、代理断线、设置保存和历史冻结；不证明真实 VPS 的线路、带宽、平台风控或 Windows 行为。系统/浏览器管理策略及本机网络工具会影响实际运行，部署时还须核对三个环境的实际出口。IP 探测是该时刻的观察，不代表所有域名、全部时段的流量抓包证明。

视频上传也经过 VPS；采购时同时核对出站流量与持续带宽，不能只按登录网页的用量估算。
